# Book registry — every trading book the worker runs

**Canonical index of every book that writes `paper_trades` (or trades live).** The strategy
status loop reconciles the live `paper_trades.strategy` rows against this table every run: a
`book:<tag>` the query finds with **no row here is UNTRACKED** — the loop flags it (a book must
never trade without its rationale + pre-registered gate written down where the loop can see it).

**Who maintains this:** whoever builds or changes a book. The `kalshi-strategy` skill's Phase 5
(paper trade) REQUIRES adding a row here the moment a new book starts writing `paper_trades`, and
Phase 6 (live) REQUIRES updating its `status`. This file lives on the default branch (unlike the
loop's `STRATEGY_LOOP_STATUS.md`, which lives on `strategy-loop-status` and is loop-owned), so a
build/fable session can update it in the same PR that adds the book. Newest books at the top.

The `tag` column MUST match `paper_trades.strategy` exactly (or its prefix for a variant family),
so the loop can join on it. Keep the gate one line; the linked thesis doc carries the full detail.

## FEE RE-BASELINE — 2026-08-11. Read this before applying ANY gate below.

The paper engine billed resting maker entries at Kalshi's **taker** rate, ceiled to a whole cent
per order: **1.000¢/contract** against the **0.003¢** Kalshi actually charges a maker (measured,
n=342 live fills). The engine was corrected on **2026-08-11** (`kalshi_fee(..., maker=True)`).

**Size of the correction: +0.85 to +0.89¢/contract** in the 5–10¢ yes band (+0.89¢ at a 93¢ NO
entry). Every maker-book number is that much better than it used to read — the trade did not
change, only the bookkeeping.

**The boundary is a date, not a flag.** Maker-book history now spans two fee models, split at the
2026-08-11 deploy. A gate read across it must restrict to post-boundary trades or add the
difference back. The three live pairs got fresh `_pt3` twin epochs at the same deploy so the
comparisons that decide promotion sit entirely on one model.

**`mmsell_fill_model` handles this for you.** It normalizes every P&L to one fee model — adding
back the fee actually charged (stored per row) and re-applying the maker fee — so its `real_$/ct`
column and its EDGE/MIRAGE labels are already fee-model-independent and need no manual
adjustment. The `> +0.87¢` re-reads below are for gates applied to figures computed ANYWHERE ELSE
(a hand-written query, an older report, a number quoted in a doc before this date).

**What the correction does NOT rescue.** It is uniform across maker books, so it never reverses a
*relative* verdict. A book losing to its control still loses to it; the 2026-08-09 finding that
the wide band is dead (control `mmsell` at −1.80¢/trade, ≈−0.93¢ corrected) survives intact. The
correction moves the whole maker cohort up together — it does not re-rank it.

### Which gates moved, and which did not

| gate shape | fee-sensitive? | why |
|---|---|---|
| **Relative** — "beat control by ≥X¢", "Δmean ≥ −0.3¢", "beat `mmsell10a` by ≥0.5¢" | **NO** | both sides are maker books at the same clip, so the fee shifts them equally and cancels in the difference. The A1–A4 and offset-A/B gates are purely this shape and stand **unchanged**; the W/T gates contain a relative clause of this shape *plus* absolute clauses (next rows) that do move. |
| **Absolute paper** — theta4's "per-trade > 0", and the W/T families' "own ¢/trade > 0 absolute" (added 2026-08-09) | **YES** | now ~0.87¢ easier. Re-read as **> +0.87¢** on pre-boundary trades to preserve the bar that was actually intended. |
| **Realizable** — "realizable ¢/trade > 0" | **YES** | `mmsell_fill_model` computes realizable as *paper* P&L over the tickers live actually filled, so it carries the paper fee. Re-read as **> +0.87¢** on pre-boundary data. (The script itself now normalizes this — see below.) |
| **Break-even win rate** — A5's 93.9% | **YES** | the fee sits inside the break-even: p = (100 − entry + fee)/100. At a 7¢ entry, 93.9% was computed with the ~1¢ taker fee; with the maker fee it is **93.1%**. A5's n≥82 was sized against the old bar and is now conservative. |
| **Weather books** | **NO** | they enter at the ask — genuine takers, formula unchanged. Their −5.0¢/trade is real. |

### The MIRAGE verdicts must be re-read

Five books were labelled MIRAGE on a realizable figure between −0.24¢ and −0.85¢. Adding back the
0.87¢ the simulator was over-charging puts **all five at or slightly above zero** — they are
marginal, not negative:

| book | realizable as measured | + fee correction |
|---|---|---|
| `mmsell3` | −0.85¢ | ≈ +0.02¢ |
| `mmsell11` | −0.83¢ | ≈ +0.04¢ |
| `mmsell4` | −0.82¢ | ≈ +0.05¢ |
| `mmsell7` | −0.28¢ | ≈ +0.59¢ |
| `mmsell6` | −0.24¢ | ≈ +0.63¢ |

**This is a validation of the fix, not a rescue of the books.** Live `mmsell3` realized
**+0.18¢/trade** over n=359 before it was closed (`docs/MMSELL_LIVE_POSTMORTEM.md`) — the
corrected realizable estimate of ≈+0.02¢ lands on that live ground truth, where the −0.85¢
reading contradicted it by a full cent. The postmortem's conclusion is unchanged: `mmsell3` is
**breakeven, not profitable**, and breakeven is still not worth live capital. What changes is that
"MIRAGE" overstated the case — the correct verdict is "indistinguishable from zero".
