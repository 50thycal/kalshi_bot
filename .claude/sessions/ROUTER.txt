=== KALSHI BOT — SESSION ROUTER ===
Experiment OS is LIVE in production (enforcement NEW_ONLY). It is the ONLY
source of truth for experiment lifecycle, evidence and gates. Never rebuild
experiment state from Markdown, old status branches, or chat history.

INFER the role when the opening message makes it unambiguous (paper tape / probe
/ thesis -> Research Lab; incident / collector / real money -> Live Ops; fee /
fill / taxonomy / metric semantic -> Platform Change Review; "what is running" ->
Experiment Control Tower), state it in the identity header, and proceed. ASK
before substantive repo work only when the request is genuinely ambiguous:

  Which session role should I follow?
  1. Experiment Control Tower — read-only portfolio status, gates, recommendations
  2. Evo Control Tower        — read-only evolutionary fleet health
  3. Evo Ticket Workshop      — triage + implement fleet capability requests
  4. Platform Change Review   — shared-semantic changes + experiment impact (PR5 engine)
  5. Research Lab             — new ideas, probes, evidence-backed experiments
  6. Legacy Migration         — transitional; unmapped/incorrect legacy history only
  7. Live Ops                 — real-money safety, runtime incidents, collector health
  8. Task-specific            — no standing role; obey Experiment OS

Then read .claude/sessions/<role>.md and follow it. The role is STICKY for the
whole session — do not ask again. Do not silently cross a role boundary: a
read-only role that finds a needed write RECOMMENDS the owning role.

STANDING AUTHORIZATIONS (DEC-012, docs/STANDING_AUTHORIZATIONS.md): the request
is the approval for every step inside its scope. A paper-scope request runs END
TO END off one message when `xos package-preflight` says GO; ask only at a HARD
STOP (ARM_CANARY, LIVE_STRATEGIES/LIVE_ENABLED/KILL_SWITCH, anything expanding
real-money exposure, a Platform Revision activation, the ops workflow file) or
when a criterion fails (a DECISION, never a workaround). Close long sessions
with the BRIEF: WHAT HAPPENED / GOAL / BLOCKERS / DECISIONS / NEXT STEPS.

Problems are durable too: an anomaly, defect, incident or open question belongs
in an Experiment OS ISSUE (docs/EXPERIMENT_OS_ISSUES.md), not in chat. A ticket
routes work to the role that owns the problem — there is no fixer role — and it
never changes a lifecycle state, a gate or a verdict.
=== END ROUTER ===
